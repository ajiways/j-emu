# Мана в бою и идолы

Статус: **реализовано** (раздел «Реализация»); остальное — исследование 2026-10-01 и открытые вопросы.
Источники: каталог Pub1 (`content/pub1-items.generated.json`), тексты `images/locale/ru/amf/
artifact_artikul_*.amf`, live-дамп `_research/giga_dump_2026-08-11/_timeline.json` (PvP, hero
`ajiwaysss`, идол 3809) и `_research/new_usable_session/`. Старый `../server` идолы игрока не
реализовывал (только призыв мобов kind 10 у ботов).

## Что такое идол

- Предмет в **сумке** (`action:"bag"`, `slot_mask 0`, `kind_id 35`; `type_id` 21 «бронзовый»,
  71 «серебряный/золотой/легендарный/редкий», ещё 57/133/…). Всего ~190 с заклинанием.
- Заклинание одно: `targetRestr {self:true}`, эффект `kind 10` с `botArtikulId` = моб-**фантом**,
  который «однократно призывается в бой, сражается на стороне призвавшего и исчезает по
  окончании боя». Предмет расходуется (`persSpells.count 1`).
- В бою идол приходит в `persSpells` как `srcType:4`, `srcId` = instance id предмета,
  `flags:"48"`, `mpCost`, `targetRestr {self:true}`.

## Два вида идолов (данные и описание совпадают)

| Вид           | Признак в данных                                           | Текст                                  | Статы фантома                                                                                                |
| ------------- | ---------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Фиксированный | `spell.mpCost = N`, у предмета `skills` STR/VIT/LUCK       | «требуется N маны»                     | берутся с предмета (STR ≈ 5,6 на ману, VIT 3–6 на ману; «Гарпина [13]»: 25 маны → STR 141, VIT 125, LUCK 25) |
| «До N маны»   | `spell.mpCost = 1`, в эффекте `manaCost = M`, `skills: []` | «требуется **до** M+1 маны» (M+mpCost) | масштабируются затраченной маной; формулы в данных нет                                                       |

Живой образец «до N»: «Серебряный идол Гарпины [15]» (`mpCost 1`, `manaCost 38`, до 39). Герой 7-го
уровня с `maxMp 21`, `mp 21`:

- запрос клиента: `castSpell {srcType:4, srcId:<instance>, targetId:<self>}` — **без количества
  маны**; ответ HTTP пуст;
- сервер списал **всю** ману: `{et:"mpChange", delta:-21, persId}` и `persChangeInfo mp:0`;
- появился `persChangeInfo` моба: `bot:true`, `artikulId:"550"`, «Стойкий фантом Гарпины»,
  `level 15`, `hp/maxHp 158`, `team` = команда призвавшего, `maxMp 0`; потом врагу пришёл
  `oppnew` с этим фантомом (`body "ghost(0,1,0)"`, `sk "52"`, avatar `avatar_garpina1_sm.jpg`):
  фантом встаёт в очередь участников и спаривается как обычный моб.
- Вывод (из одной точки): трата = `min(mp, mpCost+manaCost)`, не меньше `mpCost`; всё доступное до
  предела.

## Чего нет и что нужно решить

- **Статы фантомов.** В `bots_info.amf` у фантомов только `id/nick/level/flags`; в нашем каталоге
  ботов их нет. Для фиксированных статы — с предмета; для «до N» нужна формула от затраченной
  маны (предположение: пропорционально, коэффициент с «братьев» фиксированного вида; одна живая
  точка: 21 маны → hp 158 у фантома 550).
- **Откуда идолы в бою:** все идолы сумки без лимита (решение владельца), список не прячется.
  Обычного идола можно призывать сколько угодно, пока хватает маны. Сильные идолы ограничены
  «один фантом такой группы на бой»; в каталоге у идолов группы пока нет (`groupId` пусто,
  `selgroupdeny` везде `{}`), то есть ограничен пока никто — группу выставляет контент.
  Для ручной проверки идолу 305 («Бронзовый идол Грызла [5]») выставлена тестовая группа 9305
  прямо в `content/pub1-items.generated.json`; пересборка декодером её сотрёт.
- **Мана:** `maxMp` героя (у 7 ур. 21), восстановление в бою не замечено; `MPMAX` навык.
  Другие траты: заклинания с `spell.mpCost` (аграфы «Бездны» kind 4 — 50 маны, тип 7/163),
  `manaCost` у зарядных заклинаний (Град выстрелов).
- Wire: `mpChange` (delta, persId) всем, `persChangeInfo` с `mp`, `persList`/`persChangeInfo` нового
  моба, `oppnew` паре, `persSpells` без потраченного идола.

## Реализация

- **Мана.** `Participant.mp/maxMp` (`MPMAX` — поддержанный навык). Тратят `castSpell` и мгновенные
  касты (`spell-mana.ts`): `mpCost` спелла, у «до N» — всё доступное до `mpCost + Σ manaCost`.
  Нехватка — `FightCastDenied("mana")` до расхода предмета. В бою мана не восстанавливается;
  остаток пишется в героя при завершении боя (`persistFightResources`: мана первой, затем hp/смерть).
  Wire: `mpChange` + `persChangeInfo` кастера. Мана ботов 0, спеллы мобов без `mpCost`.
- **Лимит группы.** Идол, у чьего `spell.groupId` есть значение, нельзя призвать, если в бою уже
  есть фантом той же группы (любой игрок, даже погибший): тихий `{rs:false}`
  (`FightCastDenied("phantom")`), предмет и мана целы. Идол без группы не ограничен.
- **Идолы.** Клиент рисует идолов в «правом кармане» (`PocketTypes.RIGHT`): его слоты строятся из
  предметов мешка с `show_extern` (разбор `pocket.swf`), а `persSpells` лишь обновляет слоты по
  `srcId`. Поэтому мешок отдаёт `show_extern: true` для идолов (`isIdolArtifact`: kind 35 +
  спелл с kind 10; среди живых kind-35 предметов true был только у идола). Все идолы мешка (`kindId 35`, `extra.spell` с kind 10) входят в `CombatLoadout.idols`
  и в `persSpells` как `srcType 4` (`flags "48"`, `mpCost`, `count`). `castSpell srcType 4`
  → `Battle.tryIdol` → `tryIdolCast`: списывает ману, добавляет `BotFighter` фантома в команду
  кастера (id из эфемерного диапазона), ждёт врага как обычный моб; `roster-updated` показывает
  всем нового участника, `armFightClocks` парует ждущих. Предмет мешка тратится через
  `consumeBagItem` в HTTP-команде (как карман).
- **Фантомы** — боты `bots-overlay.json` с id = `botArtikulId` идола. Фиксированные идолы: STR/VIT
  предмета. «До N»: полная сила = `5.7·STR` и `7.5·VIT` на ману (по живой точке 21 маны → hp 158),
  в бою масштаб `потрачено / (mpCost+manaCost)`. Внешний вид — по ближайшему существу той же
  семьи (sk/avatar), `body ghost(0,1,0)`; это догадка, не live. Сгенерировано 65 из 104
  фантомов идолов; у остальных (например зомби, убийца, духи Лазло) нет записи: идол в списке
  есть, каст падает явной ошибкой `absent from the catalog`. Дописывать в `bots-overlay.json`.
- Проверка: `/scenario idols`, e2e `idols` в `tests/e2e/fight-scenario.test.ts`,
  `tests/unit/combat/idol-summon.test.ts`, `spell-mana.test.ts`.
