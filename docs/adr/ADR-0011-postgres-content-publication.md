# ADR-0011: Публикация контента через PostgreSQL

- Status: Accepted
- Date: 2026-09-07
- Supersedes: [ADR-0005](ADR-0005-content-storage.md)

## Контекст

Контент должен редактироваться, проверяться, публиковаться и откатываться без двух источников истины. Файлы старого `jgr-emu`, материалы `_research`, дампы и fixtures полезны для первоначального импорта и проверки совместимости, но не подходят как рабочее хранилище нового runtime.

ADR-0005 назначал authored-файлы в Git источником истины. Это больше не соответствует выбранному редакторскому процессу с серверными версиями черновиков. Настоящий ADR полностью заменяет это решение.

## Решение

Используется один PostgreSQL:

1. Редактор записывает только версионированные черновики в schema `content`.
2. Валидация читает конкретные версии черновиков и создаёт immutable логический release bundle: manifest, checksum, версии схем и точные ссылки на входные версии.
3. Импорт раскладывает bundle в новые строки версионированных runtime-таблиц.
4. Одна транзакция активирует целую release version только после успешной загрузки и проверки всех её частей.
5. Runtime читает только активную версию из PostgreSQL. Он не читает черновики, fixtures, дампы или файлы старого репозитория.

Любая невалидная строка, неизвестное поле, отсутствующая ссылка или несовместимая версия отменяет весь candidate release. Частичная публикация и режим «пропустить ошибочное» запрещены.

Dual-write отсутствует: одна пользовательская операция не пишет одновременно в файлы и runtime-таблицы. Редактор не меняет опубликованные строки, а importer не исправляет черновики.

На первом этапе не вводятся SQLite, object storage, брокер сообщений и отдельный content microservice. Пайплайн работает внутри модульного монолита и одной БД через явные application ports. Эти компоненты можно рассматривать только после появления измеренной эксплуатационной необходимости.

Seed предназначен только для bootstrap пустой БД. Он импортирует явно заданный исходный corpus и идемпотентен по digest источника: повтор с тем же digest не создаёт новые черновики или release. Seed не является штатным способом обновления работающей среды.

Экспорт и импорт immutable release bundle — явная recovery-операция. Экспорт содержит manifest, checksum, версии схем и данные release; импорт проверяет всё содержимое до записи и не активирует release автоматически без отдельной команды.

## Последствия

- PostgreSQL является единственным изменяемым источником истины для authored и опубликованного контента.
- Черновик, проверенный bundle и активная runtime revision имеют разные состояния и не смешиваются.
- Откат выбирает ранее опубликованную совместимую release version; опубликованные строки не редактируются.
- Полная ссылочная проверка и детерминированный checksum становятся обязательной частью публикации.
- Резервное восстановление не зависит от Git checkout старых fixtures, но требует проверяемого export release.

## Не является частью решения

- перенос старого runtime-кода или его подключение как библиотеки;
- чтение runtime из `jgr-emu/fixtures`, `_research` или дампов;
- синхронизация PostgreSQL с authored-файлами;
- распределённая оркестрация публикации.

## Пересмотреть, когда

- измеренный объём bundle не укладывается в допустимое время одной публикации;
- один PostgreSQL перестанет обеспечивать требуемые доступность или объём;
- появится независимый content-team lifecycle, требующий отдельного сервиса;
- восстановление из database backup и release export окажется недостаточным по подтверждённым требованиям.
