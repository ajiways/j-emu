# Quest engine: целевая persistence model

> **Статус:** план Drizzle/PostgreSQL. Имена могут уточняться до миграции, но
> ownership, identity, уникальности и transaction semantics являются частью
> контракта.

## Принципы

- authored source живёт в общем `content` draft/release lifecycle;
- runtime никогда не читает draft;
- compiled definition immutable и адресуется `(releaseId, questKey)`;
- run имеет собственный PostgreSQL identity и pin на release;
- повторяемый квест создаёт новый run/cycle, а не перезаписывает историю;
- state, receipt и DB-effects одной transition сохраняются в общей UoW;
- JSONB допустим для immutable compiled payload/snapshot, но не заменяет
  constraints на lifecycle и конкурентные записи;
- runtime wire ids находятся в `1..2_147_483_647` и выдаются PostgreSQL, если
  не импортирован подтверждённый authored id.

## Definition/materialization tables

### `quests.definition_revisions`

| Column                      | Contract                                                    |
| --------------------------- | ----------------------------------------------------------- |
| `release_id uuid`           | FK `content.releases`, часть PK                             |
| `quest_key text`            | стабильный authored key, часть PK                           |
| `source_digest text`        | semantic source digest                                      |
| `schema_version text`       | версия quest authoring language                             |
| `book_id integer`           | legacy journal identity                                     |
| `kind text`                 | normal/story/repeatable/exchange и т. п. presentation class |
| `title_snapshot text`       | быстрый список/history fallback                             |
| `compiled jsonb`            | полностью validated executable snapshot                     |
| `compatibility_digest text` | impact comparison                                           |

Unique `(release_id, book_id)`. Размер compiled document ограничен. Definition
не обновляется после activation; новый release создаёт новые строки.

### `quests.host_entries`

Компилированный индекс доски: `release_id`, `host_type`, `host_key`,
`entry_key`, `owner_type`, `owner_key`, `scene_key`, `sort_order`, marker intent.
PK включает release/host/entry; owner reference проверяется materializer.

### `quests.event_interests`

Индекс для routing/projection, а не progress: `release_id`, `quest_key`,
`event_kind`, optional catalog/entity discriminator. Он позволяет не сканировать
весь release, но active run/stage всё равно проверяется authoritative engine.

### `quests.wire_identities`

Stable registry для `book`, `point`, `answer`, `target`, `counter`:

```text
(identity_kind, owner_key, semantic_key) primary key
wire_id integer unique, generated by PostgreSQL sequence
legacy_fixed boolean
```

Imported confirmed id резервируется как authored value после collision check;
новый editor content получает sequence id. Counter id глобально уникален, так
как старый клиент ищет его без quest id. Удалённая semantic identity не
переиспользуется.

### `quests.availability_projections`

Compiled legacy static record для NPC/map marker: release, NPC, quest, title,
level/faction и adapter-supported restrictions. Это производная authoritative
conditions, а не второй authoring source.

## Runtime aggregate

### `quests.runs`

| Column                                   | Contract                                                       |
| ---------------------------------------- | -------------------------------------------------------------- |
| `id bigint generated always as identity` | внутренний runtime run id; наружу по wire не передаётся        |
| `hero_id integer`                        | FK hero, mandatory                                             |
| `quest_key text`                         | stable content key                                             |
| `definition_release_id uuid`             | pinned immutable revision                                      |
| `cycle_key text`                         | authored repeat-window identity                                |
| `attempt_no integer`                     | монотонен для hero/quest                                       |
| `status text`                            | `active`, `ready`, `completed`, `cancelled`, reserved `failed` |
| `active_stage_key text`                  | null только terminal                                           |
| `revision integer`                       | optimistic/stale-command token                                 |
| timestamps                               | started/ready/finished/cancelled                               |
| terminal fields                          | reason, ending/reward ids                                      |

Constraints:

- unique `(hero_id, quest_key, attempt_no)`;
- unique `(hero_id, quest_key, cycle_key)` для policies с одним claim/cycle;
- partial unique active run на `(hero_id, quest_key)` для baseline;
- status/timestamps согласованы check constraint;
- pinned `(definition_release_id, quest_key)` существует.

В TypeScript `bigint` identity представляется branded decimal string либо
нативным `bigint`, но не `number`: это исключает потерю точности и случайную
утечку внутреннего id в legacy wire. Все FK на run используют тот же `bigint`.

### `quests.stage_instances`

`run_id`, `stage_key`, `activation_no`, status
`active|completed|skipped|cancelled`, timestamps и `journal_snapshot jsonb`.
PK `(run_id, stage_key, activation_no)`. Partial unique допускает ровно один
active stage на run. Finished rows питают историю целей, не future leakage.

### `quests.requirement_progress`

`stage_instance_id`, `requirement_key`, typed `value jsonb`, numeric projection,
limit, `satisfied`, generation и updated timestamp. PK по stage/requirement.
Форма value валидируется registry при чтении/записи; numeric columns существуют
для counters и range bindings.

### `quests.run_decisions`

Append-only choice/outcome: run, decision key, activation, selected option,
input snapshot, result, edge, operation key и created_at. Unique гарантирует
один committed результат на activation. RNG/check результат не пересчитывается.

### `quests.run_facts`

Локальная память попытки: `(run_id, fact_key)`, typed value и updated_at. Не
смешивается с permanent personal world state.

## Dialog persistence

### `quests.dialog_sessions`

Identity, hero, definition release, scene/entry/host, optional run id,
activation token, current node, status `open|completed|closed|invalidated`,
resume policy, revision и timestamps. Partial unique запрещает две открытые
session одной scene activation.

### `quests.dialog_decisions`

Session, node, attempt number, option/check input snapshot, roll/modifiers,
result edge, command id и timestamp. Unique `(session_id, node_key, attempt_no)`
и unique command id делают reopen/retry безопасными.

Закрытие UI само по себе не удаляет session. `restart_on_close` явно создаёт
новую activation/attempt только согласно authored policy.

## Exactly-once и asynchronous work

### `quests.command_receipts`

`operation_id` PK, hero, command kind, canonical input digest, state
`executing|succeeded|denied|failed`, semantic result snapshot и timestamps.
Повтор одинакового завершённого command возвращает сохранённый result; другой
digest с тем же id является conflict. Это не обещает dedup двух legacy wire
requests без общего request id.

### `quests.event_receipts`

`event_id`, `run_id`, `event_kind`, payload digest, disposition
`applied|ignored`, ignore reason, observed/applied revision и timestamp. PK
`(event_id, run_id)`. Повтор с другим digest является ошибкой, а не no-op.

### `quests.effect_receipts`

`operation_key` PK, run/transition/effect identity, executor type, result
snapshot и timestamp. Нужен для effects, чей owning service не имеет собственного
operation-id store. Если receiver уже гарантирует idempotency, здесь всё равно
остаётся audit link transition → receiver operation.

### `quests.operations`

Durable intents для действий вне DB transaction:

- identity и unique operation key;
- type/payload snapshot;
- state `pending|claimed|succeeded|retryable|failed|cancelled`;
- available_at, lease_until, attempts, last_error;
- run/session/encounter owner.

Workers используют `FOR UPDATE SKIP LOCKED`; expired lease возвращает intent в
retry. Unsupported operation fail-fast и не помечается succeeded.

### `runtime.game_fact_outbox`

Shared durable facts, которые owning subsystem пишет в той же UoW со своей
mutation: fact id/kind/schema version, payload/digest, occurred time, producer
operation/causation, delivery state, lease/attempt/error. Таблица намеренно не
лежит в `quests`: combat/inventory/store являются владельцами факта, а quest
engine — одним из consumers. Полный contract:
[OPERATIONS_AND_WAITS_V1.md](OPERATIONS_AND_WAITS_V1.md).

### `quests.waits`

Quest-owned timer: run/session, wait key, generation, `started_at`, `due_at`,
state `scheduled|claimed|completed|cancelled`, lease, presentation snapshot и
completion event/operation keys. Unique active wait на owner/generation. Время
клиента вычисляется из persisted timestamps.

### `quests.encounters`

Run/stage binding, encounter key/generation, state
`ready|start_pending|active|terminal_pending|won|lost|abandoned|recovery`,
start operation key, fight id nullable, roster/participant snapshot, seed,
recovery policy, terminal fact id и timestamps. Unique fight id и unique active
encounter generation. Terminal event закрывает строку через receipt. Полный
contract: [ENCOUNTER_COORDINATOR_V1.md](ENCOUNTER_COORDINATOR_V1.md).

## Assets, outcomes и history

### `inventory.item_lots` (cross-module dependency)

Inventory stack quantity разбивается на provenance lots: item row, quantity,
origin operation, optional quest asset owner/generation и transfer policy.
Сумма lots равна quantity stack row; split/merge/consume сохраняют origins.
Quest schema только ссылается на owner/operation и не владеет lots. Полная
модель: [INVENTORY_PROVENANCE_V1.md](INVENTORY_PROVENANCE_V1.md).

### `quests.asset_grants`

Ledger: run, effect operation, asset key/generation, asset type, catalog id,
optional inventory instance id, granted/remaining quantity, expiry, state
`temporary|consumed|lost|reissued|permanent|cleaned`, cleanup/recovery policies.

Для stackable предметов inventory port должен вернуть фактические created/merged
lots. Нельзя очищать «все предметы artikul X». Если текущий inventory не может
сохранить provenance после merge/split, quest item либо выдаётся отдельным
instance, либо inventory получает provenance-aware lot support до реализации
такого квеста.

Целевое решение — provenance lots из
[INVENTORY_PROVENANCE_V1.md](INVENTORY_PROVENANCE_V1.md); отдельный
несмешиваемый instance допустим только как ограниченный промежуточный tracer, не
как финальная модель stackable assets.

### `quests.hero_world_facts`

Permanent personal state: hero, fact key, typed value, source outcome/run,
version и timestamps. PK `(hero_id, fact_key)`. Named outcome с несколькими
facts применяет их одной UoW и одним outcome receipt.

### `quests.run_history`

Immutable terminal summary: run id, hero, quest/release, lifecycle result,
cycle, ending/reward, title/summary snapshot и timestamps. Unique run id.
Operational stage/requirement rows можно чистить только после создания history
и окончания retention; history и committed world facts не удаляются при
архивации definition.

### `quests.repeat_claims`

Hero, quest, track key, cycle key, claimed_at и next_available_at. Это отдельный
namespace от run completion и activity tier claim. Unique предотвращает двойную
награду в одном cycle.

### `quests.activity_progress` / `quests.activity_claim_tracks`

Activity progress хранит hero/activity/release, challenge index, unlocked tier,
active encounter и revision. Claim track отдельно хранит tier snapshot,
last/next available timestamps и claim revision. Progress challenge не
сбрасывается получением периодической награды.

### `quests.service_invocations`

Hero/provider/route, quote/source/destination/payment/presentation snapshots,
state `quoted|waiting|committing|completed|cancelled|failed`, wait id,
operation/revision/timestamps. Travel service использует эту state machine, а не
quest run. Полная семантика activity/service:
[REPEAT_ACTIVITIES_SERVICES_V1.md](REPEAT_ACTIVITIES_SERVICES_V1.md).

## Projection state

`quests.projection_revisions` хранит hero id, monotonically increasing revision
и dirty mask/keys для journal, board, world overlay и marker refresh. Это не
кэш доменной истины. Projection builder читает committed state и может полностью
восстановить ответ после restart.

Wire macro dictionaries не сохраняются с ephemeral hashes. History/stage
snapshot хранит semantic rich fragments; adapter компилирует новый dictionary
для каждого response.

## Индексы

Минимально нужны:

- runs `(hero_id, status)` и `(quest_key, status)`;
- stage partial active by run;
- waits `(state, due_at)`;
- operations `(state, available_at)` и lease;
- encounters `(fight_id)` и active owner;
- assets `(run_id, state)` и `(inventory_item_id)`;
- world facts `(hero_id, fact_key)`;
- event/effect operation keys;
- host entries `(release_id, host_type, host_key, sort_order)`;
- event interests `(release_id, event_kind, discriminator)`.

Index создаётся только под названный query path и подтверждается integration
test/`EXPLAIN` на representative volume.

## Cancellation transaction

`cancel(runId, reason)` под hero/run lock:

1. проверяет cancel policy и expected revision;
2. закрывает active session/wait/encounter activation;
3. планирует cleanup только temporary asset ledger rows;
4. выполняет DB cleanup через owning ports;
5. сохраняет terminal run + immutable history;
6. отменяет ещё не dispatch-нутые operations;
7. записывает внешние cleanup intents;
8. помечает projections dirty;
9. commit.

Повтор команды возвращает тот же terminal result. Permanent outcome/rewards не
откатываются, если policy явно не говорит обратное.

## Publication impact

Activation compatibility query использует `quests.runs(quest_key,status)` и
semantic digests. Для changed/removed definition создаётся отчёт:

```text
quest key → active run count → cleanup kinds → cancellable yes/no
```

Новый release не активируется, пока все affected runs не переведены в terminal
state. Completed `run_history` остаётся связанной со старым release. Архивация
без изменения definition запрещает новые runs, но не требует переписывать
history.

## Migration boundary

Текущие `hero_quests/hero_quest_goals/hero_facts` удаляются вместе со старым
runtime. Данные не мигрируются и не попадают в новую history: production нет, а
семантически достоверное преобразование всё равно невозможно. Старый authored
content также удаляется; нужные реальные квесты позднее импортируются через
новую schema version и полную candidate validation.
