# Ручная проверка CEF

Список клиентских сценариев Wave 0–12, которые агент **не прогонял** в CEF
(Flash/Pub1 на `s1.jugger.ru`). Это отдельный операторский backlog уже
закрытых capability: вычёркивание строки поднимает product-status в
[CAPABILITIES.md](../CAPABILITIES.md), не сдвигает `ROADMAP.md`.

Исключение «Отложенный CEF Wave 5–12» **закрыто** (EDT-02). Новые capability
с production consumer нельзя закрывать без CEF. Проход строк ниже — Wave 0
→ 12, не вперемешку. Новый герой, штатные `npm run db:reset` / `start:https`,
без ручного patch БД. Контент менять HTTP `/operator/content/*` (не SQL).
После успешного клика вычеркни строку и подними product-status только
вместе с CEF-фактом в `CAPABILITIES.md`.

Выдача предмета и `money_minor` больше не требует патча БД: модуль
«Персонаж» в `j-content-editor` (CHAR-01) ходит в `/operator/hero/*`.
Нового героя без Flash создаёт `npm run dev:bootstrap-hero` против
запущенного `npm run dev` (печатает `heroId`).

### Сценарии боя из чата (инструмент проверки)

Редкие ситуации (смерть от тика, диспел бота против бота, стан бота) ловить в
обычной игре нереально, поэтому бой можно запустить по сценарию. Сообщение в
чат (любой канал) `/scenario <имя>` стартует сценарий для отправителя, а
`/scenario` без имени перечисляет доступные. Сообщение в общий чат не уходит.

- Сценарии: по одному JSON на файл в `config/fight-scenarios/`, имя файла = имя
  сценария (kebab-case). Поля обязательны, неизвестные и пропущенные поля —
  ошибка при старте сервера: `description`, `purpose`, `hero.hp`, `enemies[]`, `allies[]`;
  `hero.glove` (`null` или `hits`[8] и `spells`[`artikulId`, `cost`, `row`] — перчатка
  на время боя вместо надетой), `purpose` (`hunt` — один бот без союзников, `quest` — состав с союзниками или
  несколькими врагами; у `quest` нет кнопки «выйти»);
  бот: `botArtikulId` (внешность из каталога), `hp`, `strength`, `nothingWeight`,
  `spells[]` (`artikulId` заклинания, `slot`, `weight`, `maxCasts`, `gate`,
  `hpPct`).
- Включение: `FIGHT_SCENARIOS_DIR` в `.env` (пусто — выключено, тогда
  `/scenario ...` остаётся обычным сообщением). Значения по умолчанию нет.
- Герой стартует с `hero.hp` (не больше его максимума, иначе системная строка с
  объяснением). Бой обычный: поведение героя после него как у обычной охоты.
- Неизвестное имя — системная строка в чат со списком сценариев.
- Новый сценарий = новый файл, перезапуск сервера. Те же файлы используют
  e2e-тесты (`tests/e2e/fight-scenario.test.ts`).
